# Coding Guidelines & Standards

This document establishes mandatory coding standards, linting rules, error handling conventions, and code organization practices for **Grahvani**.

---

## 1. Python / FastAPI Guidelines

### 1.1 Code Formatting & Linting
- **Linter / Formatter**: Use **`ruff`** for linting and formatting. Line length target is **100 characters**.
- **Type Annotations**: 100% type annotation coverage is required for all function arguments and return signatures.
- **Python 3.12 Syntax**: Use modern Python type syntax:
  - Use `list[str]` instead of `typing.List[str]`.
  - Use `str | None` instead of `typing.Optional[str]`.
  - Use `type` alias keyword for custom type definitions.

```python
# GOOD: Modern, typed Python 3.12 signature
async def calculate_birth_chart(
    profile_id: str,
    ayanamsha_id: int = 1,
) -> ChartSnapshotResponse:
    ...
```

### 1.2 Pydantic & API Schemas
- Use Pydantic v2 `BaseModel` for all API request/response contracts.
- Use explicit field validations with `Field(ge=..., le=...)` for lat/long coordinates and dates.
- Use `ConfigDict(extra="forbid")` on input schemas to reject unexpected parameters.

### 1.3 Error Handling
- Never swallow exceptions with silent `try: ... except: pass`.
- Raise domain-specific custom exceptions inheriting from `GrahvaniException`.
- FastAPI exception handlers convert domain exceptions to RFC 7807 Problem Details JSON format.

```python
# GOOD: Structured Domain Exception
class EphemerisCalculationError(GrahvaniException):
    def __init__(self, detail: str):
        super().__init__(
            status_code=422,
            error_code="EPHEMERIS_CALCULATION_FAILED",
            message=detail,
        )
```

## 2. Dart / Flutter Guidelines

### 2.1 Code Formatting & Linting
- Enforce standard `flutter_lints` rules with strict raw strings and immutability checks.
- Format code using `dart format --line-length 80`.
- All widget constructors must be `const` wherever possible.

### 2.2 Riverpod State Management
- Never instantiate state mutable global variables outside providers.
- Use `@riverpod` annotation for code generation providers.
- Handle state using `AsyncValue` pattern (`when(data: ..., loading: ..., error: ...)`).

```dart
// GOOD: Riverpod AsyncNotifier Provider
@riverpod
class ChartNotifier extends _$ChartNotifier {
  @override
  FutureOr<BirthChart> build(String profileId) async {
    return ref.read(chartRepositoryProvider).fetchChart(profileId);
  }
}
```

### 2.3 Layered Architecture & Imports
- Respect strict layer boundaries: `presentation` -> `domain` -> `data`.
- UI widgets must never call HTTP clients or local SQLite databases directly. All data access must pass through a repository implementation.

---

## 3. SQL & Migration Guidelines
- Table names must be lowercase, pluralized (`birth_charts`, `chat_sessions`).
- Primary keys must be UUID v4 stored as `uuid` type.
- Timestamp fields must be named `created_at` and `updated_at` stored as `TIMESTAMPTZ` in UTC.
- Every migration script generated by Alembic must feature both `upgrade()` and `downgrade()` procedures.
